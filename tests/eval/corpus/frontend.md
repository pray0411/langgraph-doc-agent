# 前端交互

前端是一个单页应用，通过 HTTP 接口与后端通信。**流式问答**走 SSE
（Server-Sent Events）通道，事件类型包括开始、文本增量、工具开始、工具结束、
完成与错误。

**事件顺序是契约的一部分**，不只是实现细节。开始事件最先到达；文本增量用于
逐字渲染回答；工具开始与工具结束必须成对出现且顺序正确，因为**高危命令的确认
弹窗依赖工具结束事件**——如果这个事件丢失，用户会看到命令被拦截却等不到确认
入口，功能直接失效。完成事件携带最终答案、过程详情与来源卡片。出错时推送错误
事件，前端展示可读提示而不是白屏。

**来源卡片**展示本次回答引用的文档片段或网页链接，让用户可以核对答案依据。
来源卡片的填充必须是**本轮**的工具调用结果：会话是多轮的，而智能体返回的消息
列表包含整个会话的累积历史，因此如果直接全量提取，第二轮回答会显示上一轮的
来源，用户会以为系统搞错了。

**过程详情面板**展示本次回答的工具调用数量、调用了哪些工具、是否基于工具结果
作答、回答长度等观测信息。其中"是否基于工具结果"通过检查回答是否复用了工具
返回文本的连续片段来判定，用于发现**幻觉式作答**：模型声称查了文档，实际回答
内容与检索结果毫无重叠。

**会话管理**支持列出历史会话、切换会话、回放历史消息。回放时会重建每一轮的
来源卡片与过程详情。成本估算按会话当时使用的服务商单价计算，而不是按回放
那一刻的配置，避免切换服务商后历史数据全部失真。

**交互终端**允许在网页里运行代码块：超文本标记语言在隔离的内联框架中执行，
Python、JavaScript 与 Shell 则在真实终端里运行，支持标准输入输出，弹窗关闭
时会自动终止子进程，避免留下孤儿进程。

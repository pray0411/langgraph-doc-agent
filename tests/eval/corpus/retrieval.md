# 检索系统

文档检索采用**混合检索**方案，由两个通道融合而成。

第一个通道是 **BM25 词法检索**。中文文本先用 **jieba** 分词，英文与数字按词切分，
随后统一小写并过滤停用词。BM25 使用经典参数 k1=1.5、b=0.75，文档频率越高的词
权重越低，因此"的、了"这类高频虚词不会主导排序。分词器不可用时自动降级为
单字加双字 bigram，保证功能不中断。

第二个通道是**语义向量检索**。使用 sentence-transformers 加载多语言句向量模型，
对查询与片段分别编码后计算余弦相似度。它的价值在于理解**同义改写**——例如用户
问"架构"，而文档里写的是"分层设计"，词法检索会漏，语义检索能命中。低于
0.2 的余弦相似度被视为无关并排除。

两个通道的结果用 **RRF（Reciprocal Rank Fusion）** 融合。RRF 只使用排名而不使用
原始分数，因此不需要在两个通道之间做分数归一化，避免了"BM25 分数与余弦相似度
量纲不同、无法直接相加"的问题。融合公式为 1/(k+rank)，k 取 60。

融合之后按分数降序截断到 top_k。**MIN_SCORE** 阈值过滤掉没有任何通道命中的
片段，避免"为了凑数而返回不相关结果"。

语义通道是**可选**的：未安装模型、模型加载失败或索引中没有向量时，检索自动
回退为纯 BM25，功能降级但不报错。这个降级路径在生产环境很重要，因为模型下载
在离线或受限网络下经常失败。

检索结果带内存缓存，缓存键包含查询、top_k、索引文件修改时间与上传文档版本号。
索引重建或用户上传新文档后，缓存自动失效。缓存满时按**最久未使用**逐条淘汰，
而不是整体清空，以免高并发下出现周期性抖动。

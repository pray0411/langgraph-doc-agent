# 安全边界

本项目允许模型调用工具执行命令、读写文件，因此安全设计必须明确说清"什么是
护栏、什么不是"。

**命令黑名单**是一组正则模式，拦截明显破坏性的操作，例如递归删除、格式化磁盘、
关机重启。必须强调：**黑名单是尽力而为的关键词启发式，不是安全边界**。
`python -c "import os; os.remove(...)"` 这类写法可以绕过关键词匹配，但它会命中
"高危命令"规则，从而触发下一道门槛。

**高危确认**才是真正的护栏。删除、移动、批量安装依赖、联网下载等操作被归为
高危，工具会返回 NEED_CONFIRM，前端弹出确认框，用户同意后才真正执行。批准凭据
是**一次性**的：使用后立即失效，并且带有五分钟有效期，避免凭据长期驻留。

**路径逃逸防护**作用于所有文件工具。写入与读取都被限制在可写根目录之内，
`../` 相对逃逸与绝对路径越界一律拒绝。这项检查基于解析后的真实路径，
而不是字符串前缀匹配，因此符号链接也不容易绕过。

**超时强杀**是最后一道防线。子进程有执行时限，超过即被终止，避免"模型跑了一个
死循环脚本，把服务拖住"。

**审计日志**独立记录每一次敏感动作：命令哈希、是否命中高危规则、是否被批准、
退出码与耗时。为了可观测性，访问日志也恢复输出，但对令牌与密钥字段做脱敏，
防止"为了排查问题反而把凭据写进日志"。

结论：本项目的命令执行能力定位是**单机个人开发辅助**，请不要在共享、生产或
含敏感数据的环境中直接对外暴露。正确做法是运行在专用隔离环境（Docker 或虚拟机）
中，以普通用户而非 root 运行，并配合访问令牌与网络访问控制。

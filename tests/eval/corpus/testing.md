# 测试体系

测试策略的核心目标是：**让别人 clone 之后能复现同一个结论**。这比"我的机器上
全绿"重要得多，也是本项目在测试上投入最多的地方。

**密封性（hermetic）** 是第一原则。测试期间禁止 `.env` 生效，禁止真实网络外呼，
并且**屏蔽代理**。前两条容易理解，第三条最隐蔽：`urllib` 在 Windows 上会回退读取
注册表里的系统代理，因此即使环境变量里没有任何代理配置，请求依然会被转发出去，
导致"装了代理软件的机器上必红、没装的机器上全绿"。这类失败看起来像产品缺陷，
实际是测试环境不密封。

**本地假模型服务**解决了"Agent 是概率系统、没法确定性地测"这个难题。测试启动一个
OpenAI 兼容的本地服务，把模型的响应用脚本编排好，然后驱动**真实的**智能体状态图
去跑。这样被验证的是真实的工具循环、真实的消息流转，但不存在网络依赖、不产生
费用、结果完全确定。此前三处创建智能体的调用全部传入空工具列表，"模型决定调用
工具、执行、观察结果、再思考"这条项目存在的全部理由，一条测试都没跑过。

**元测试（meta test）**用测试来守护测试本身：用 AST 扫描断言不存在同名用例
（同名函数会被静默覆盖，先定义的那份永远不会执行）、断言文件里定义的用例数量
与实际收集数量一致、断言 `.env` 真的被中和、断言基础地址指向本机、断言代理被
屏蔽、断言测试产生的目录落在仓库之外。这类断言的目的是让"测试套件本身退化"
变成一次可见的失败。

**测试替身的层级**也很讲究：优先替换**外部依赖**（模型服务、网络），而不是替换
业务代码内部的方法链。替换内部方法虽然写起来快，但会让"测过了"变成"测了假货"。

**覆盖率**方面，项目主动承认数字被高估：语句覆盖率包含测试自身，且前端页面
覆盖率接近零。因此在持续集成里同时输出**分支覆盖率**，并把真实缺口写进文档，
而不是展示一个好看的整数。
